1. Architectural overview

16general-purpose, writable 16-bit registers
65,536word offsets in each boot-selected segment
1 or 2physical words per retired operation; two when IMMHI12 is consumed
CMP → Ba transient pending test result links a compare to its consuming branch; there are no persistent flags

Core rules

  • All arithmetic wraps modulo 216.
  • Memory is word-addressed; one address selects one 16-bit word.
  • A physical address directly concatenates a 16-bit segment and a 16-bit offset.
  • Reset starts with CSEG = DSEG = PC = 0; applications normally keep their boot-selected segments fixed.
  • The PC normally advances before instruction semantics, so relative control flow is based on the following word.
  • All registers are architecturally writable. ABI reservations are compiler conventions, not hardwired registers.
  • CMP-class instructions leave a transient pending test result (Less/Equal/Greater). Only a conditional branch consumes it; any other retired non-prefix instruction expires it, and IMMHI12 is transparent to it. Reset leaves no pending result.
  • HALT has no encoded signal register; the architectural halt signal is r0.

Design intent

  • Small decoding surface: the high nibble selects the major operation.
  • A single transient pending test result, not persistent flags, carries a comparison outcome to its consuming branch.
  • Short immediates stay compact; IMMHI12 extends only explicitly listed consumers.
  • Near 16-bit pointers keep compiler data compact while segment registers form full physical word addresses.
  • Opcode 0xD is the blocking four-lane signed fix16 FPU family.

The offset is signed i8 relative to the already-incremented PC (±128 words). With IMMHI12 the offset widens to off16 = {prefix[7:0], imm8}: the prefix supplies the high byte and the instruction's immediate byte the low byte.

Conditions 0..5 test the pending test result, a transient three-way ordering (Less/Equal/Greater) set only by the CMP-class instructions CMPS, CMPU, CMPSI, and CMPUI. A conditional branch consumes the pending result whether or not it is taken; any other retired non-prefix instruction expires it, and IMMHI12 is transparent to it. A conditional branch with no pending result faults InvalidInstruction — reported at the prefix address when prefixed. Reset leaves no pending result.

JALREL has no link field: the link register is architecturally fixed to r14, which receives the fall-through address before the jump. Compiler-generated wide control flow uses the canonical prefix with a 16-bit wrapping relative offset.

4.7 fix16 FPU — opcode D

Each F register contains four signed Q8.8 lanes. The ISA defines exactly two uses of an F register: scalar (lane x) and vec4 (lanes xyzw); vec2/vec3 values are vec4 values with zeroed tail lanes. FPU operations are blocking, do not consume IMMHI12, and retire only after their final writeback or memory response. Narrowing rounds to nearest with ties to even and then saturates.

ACC is both the wide dot accumulator and a temporary scalar transfer register. All F registers are caller-saved and ACC is caller-clobbered; argument and return F-register assignment is a compiler-ABI decision.

5. IMMHI12 and wide operations

Canonical 16-bit immediate

F abc    AF 3 d

IMMHI12 0xabc followed by LDUI r3, 0xd loads r3 = 0xabcd. The pair is one precise architectural operation and retires two physical words together.

Closed consumer set

LOAD, STORE, immediate functions 0..4 and 8..F, and branch/jump conditions 0..5, 8, and 9 consume a pending prefix.

Shift-immediates, extended/control, register ALU, device instructions, reserved encodings, and another prefix do not consume it.

A prefix is transparent to the pending test result: an IMMHI12 sitting between a CMP-class producer and its consuming branch neither sets nor expires the test.

Precise prefix rule: a non-consumer expires the pending prefix and retires it separately. A second prefix also retires and replaces the first. If a prefixed consumer faults, the reported address is the prefix address and neither word retires.

6. Segmented addressing and ABI memory map

Physical address rule: physical_word = {segment[15:0], offset[15:0]}. There is no segment addition and a wrapping offset never carries into the segment. A fitted target may implement a smaller physical range and must report an error rather than truncate or alias an unsupported address.

Address-space contract

  • Ordinary CPU pointers cover one 65,536-word = 128-KiB segment.
  • Instruction fetch uses {CSEG, PC}; ordinary data and stack accesses use {DSEG, offset}.
  • All offsets, including 0xff00..0xffff, select ordinary memory in DSEG. Devices 0..7 are accessible only through the dedicated device instructions.
  • CompilerOptions::default() selects data base 0x4000, heap base 0x8000, and stack top 0x10000, encoded as SP = 0. CPU V3 has no v2.6 function table.
  • The CPU V3 compiler's optional code_base relocates all linked code offsets and function pointers without padding the emitted section bytes.
