# Ground shadow

The application draws the Web box shadow through an immutable unit-triangle mesh and ordinary public `Model::set_matrices` / `Pass::draw_colored` calls. Its CPU geometry consumes the already prepared player world matrix; floor, switch, well and player rendering use the same session state. The shadow is drawn after receivers and before the player, with depth test Always, depth writes disabled and SrcOver alpha 87/255, color (10,13,18). Its plane is y=393/65536. The unit mesh has a +Y normal, RGB white and no face culling. Its independent Y matrix column preserves that normal for each nondegenerate X/Z fan. The CPU receiver clipping gates the shadow to supported cells and excludes open start/goal cells. Using Always avoids rejecting coplanar shadow fragments through D16 quantization; the shadow never changes depth. Both ordinary and RTT source paths restore the opaque Less/depth-write state before drawing the player. The configured far value is an admission threshold, not a rescaling of interpolated D16 precision.

The CPU clips the eight box corners and twelve edges against y>=0, projects along (.5,1,.5), forms a convex hull, then clips it against each receiving unit cell. The box half-size is .49. Void, inactive bridges and fragile tiles hidden at CRACK start do not receive; the start opening excludes its cell during entry, and the goal excludes its cell during drop/land/close. Receiver traversal is restricted to a conservative integer hull bounding rectangle, clamped to the level dimensions. It retains inclusive boundary admission and row-major cell order, with the original exact overlap and receiver checks before clipping. Lower bounds are floored after subtracting one cell; the possible extra cell is rejected by the exact check. Row/column counters avoid per-cell division and remainder. Each cell emits a triangle fan; absolute doubled areas below 2/65536 are omitted. Sutherland–Hodgman derives the previous index from the current index. Near-zero crossing denominators scale both operands before reciprocal, and the interpolation parameter stays within [0,1].

For each receiver, the original hull extrema identify clipping planes that
already contain the entire polygon. Those planes are skipped; remaining planes
retain left/right/top/bottom order, inclusive boundaries and the same Q16
intersection arithmetic. Output alternates between the two clipping buffers;
the original hull is never a destination. Fan generation consumes the actual
last output buffer, including the unchanged hull when no clipping is needed.
This preserves vertex order and coverage while avoiding redundant polygon copies.

The immutable mesh uses white vertex colors without texture UVs. Colored draws therefore preserve the material and coverage while avoiding temporary Texture/TextureView resources and texture capture facts for each triangle. The draw counter still records the same meshlet count. No dynamic mesh upload is required. One Model is reused while each draw publishes its own Instance128 coefficients into the command buffer. Those coefficients remain valid through the normal submission/capture lifetime even after the Model changes for the next triangle. Camera changes continue through the existing renderer preparation cache.

## CPU geometry lifetime

The application caches up to 10 world-space triangle affine records, each six F16 coefficients. Exact world matrix coefficients, level generation, bridge mask and the start/goal flags and hidden fragile-cell identity form its key. Level cells are immutable between `level_reset` calls; every reset advances that generation. Projection direction, half-size, shadow height and material are program constants. A hidden player invalidates the cache. Changed animated transforms rebuild it; a cache hit still publishes ordinary native Instances with the current Camera. Hull, receiving-cell and triangle counts share `SHADOW_INFO`; there is no second cached count.

A pose with more than 10 triangles streams all its draws and disables reuse for that pose. This preserves the geometry envelope without enlarging the static cache. Integer resting first-stage/second-stage poses need at most ten triangles before receiver exclusion. The scratch buffers hold eight 3D corners, twenty projected-candidate slots, a twenty-one-point hull work chain and two twenty-four-point clipping polygons. The triangle cache reuses the dead corner/projected-candidate slots after hull construction: four records in corners and six in candidates. Hull and clipping storage remain live and independent. Scratch, key, validity and counts occupy 435u16; the level generation adds one word. Native descriptor arenas remain caller-owned and retain their normal preflight capacity checks.

For an X/Z-axis rotation of the .98×(1,2,1) box, either projected span is below three world units. At most 4×4 cells can intersect the hull. A half-space cut of a box retains at most ten corner/crossing candidates: a nondegenerate cut has at most seven faces and ten vertices, and slightly relaxing the cut preserves the closed-side sign pattern at coincident endpoints. Its two monotone chains need at most twenty working entries; the twenty-one-point hull reserves one extra entry. The application only supplies rigid/cardinal roll and scale transforms and checks this candidate bound and each hull write. Four rectangle cuts give at most fourteen polygon vertices or twelve fan triangles per cell: 192 triangles is a deliberately loose streaming bound, rather than an observed pose. Both twenty-four-point clip arrays retain a check before every write. The larger candidate array also holds six cached triangles after projection dies. Each emitted triangle uses one 128-byte Instance. The existing command and push arenas each hold 32768u16.

## Receiver-cell batching

The ordinary application uses the owned receiver-cell path. After `ground_begin`, `shadow_batch_begin` allocates one 8575-u16 heap owner (8512 usable aligned words plus at most63 alignment words). Each frame calls `shadow_batch_frame` before its frame marker to reset only the CPU-private slot cursor. Prior GPU work retires and the dynamic CB resets before `draw_shadow` mutates its selected buffer. At finite exit both CBs are dropped, then the ground and shadow owners are freed; `shadow_batch_end` clears the registered base and frees the original allocation. Without an owner the exact unit-triangle path above remains available to independent historical controls.

The allocation contains64 private words and two4224-word slots. Each slot has one CPU-private cache sector, one directory sector and16 fixed four-sector record slots. Split cubes select distinct slots in call order; neither directory nor payload of the first shadow can be overwritten by the second before submission. Each slot independently keys all twelve world coefficients, level generation, visual bridge mask and receiver flags, and retains hull/cell/triangle counts. Hidden calls invalidate their selected slot; explicit `shadow_invalidate` invalidates both slots. Batch rebuilds do not maintain or reuse the separate exact-triangle cache. A hit reuses packed world geometry; Camera changes still pass through ordinary Model preparation.

Every receiving polygon uses one meshlet, with the same row-major receiver and fan order as the exact path. Up to24 polygon entries and22 triangles fit the existing clipping buffers and one record. Original near-zero fan triangles are omitted before packing. A cell origin is exact Q16.16; X/Z vertices round to the nearest1/512 world unit (`quant_shift=7`, half-way upward), and the plane remains exactly393/65536. Grid boundaries lie on that lattice. An individual coordinate can move by at most1/1024 world unit. Using one identity Model also changes transform/narrowing grouping relative to individual affine triangle Instances, so equal source positions alone do not establish identical coverage. Tiny silhouette pixel changes are an accepted boundary of this batching path; depth writes remain disabled.

Rebuilding a record clears its header and every whole payload sector that the
maximum fan for that polygon could publish, including vertex/index padding.
The remaining tail of the fixed256-word capacity is not read by the GPU and may
retain older bytes. Fan indices use the existing six-bit native layout: vertex0
is implicit zero, and each triangle writes only its two nonzero index fields.
Three triangles still occupy one64-bit index word, with unused bits zero.

One public `Mesh::from_native` and `Pass::draw_colored` call publishes all cell meshlets in a shadow. Only the65-sector directory/record region is published as GPU storage; cache tags stay outside GPU read facts. It uses normal managed mesh validation, immutable push Instances, storage facts and submission retirement; the command ABI and profile decoder remain unchanged. The DRAW statistic counts actual meshlets. No vertices from separate cubes are unioned, and alpha order remains both shadows before either opaque cube. Record capacity and delta10 bounds are checked before publication. The supported rigid/cardinal box envelope intersects at most16 cells; the24-entry clipping bound is retained. Diagnostic quantization counters are compiled out by default and enabled only by the exploratory fixture.

## Verification boundary

The independent fixture contains actual Web world matrices and clipped polygons for standing, entry, tipping and falling. Bounded instruction-CPU tests use the normal shadow module and the functional GPU/Display, decode actual DMA/Instance commands, and check each receiver's published area and boundary. Floating triangulation counts are diagnostic: coverage is the contract. Cache verification compares changed world poses, bridges, goal receivers, level reset and hidden/visible states against forced fresh geometry. A separate bounded native CPU test uses visible stationary PLAY and actual rolling ticks. Each arm compares every START-visible command/DMA payload and generated ground storage, then complete color/depth/Display, against its identical instruction package. The candidate instruction output also matches an independently frozen accepted-source oracle. Test-only signal wrappers measure total shadow preparation and nested projection, hull, clipping and triangle command preparation, including wrapper overhead. Stationary cache hits still prepare and record every triangle; moving poses rebuild geometry. CPU/native-memory cycles exclude physical GPU/Display contention and scanout latency, so they do not measure hardware frame time.

The dedicated `bloxorz_shadow_cpu` integration target compares only the baseline shadow module against the current module with identical surrounding application/library code and assets. It runs three stationary and three rolling frames per arm with bounded instruction and native CPU execution plus a synchronous functional GPU. Each native arm checks every START-visible command/DMA input and complete physical color/depth/Display against its instruction oracle; the two arms must also match all frame pixels and depth. The emitted per-shadow cycle intervals include identical signal-wrapper observation overhead. They measure CPU/native-memory work with immediate vblank, excluding GPU cycles, scanout and physical contention. Set `BLOXORZ_SIM_OUTPUT_ROOT` to an isolated task directory and run `cargo test --release -p cpu-v3-tang-nano-20k --test bloxorz_shadow_cpu -- --ignored --nocapture --test-threads=1` through `scripts/run-cargo.ps1`.

These matrix samples qualify the shadow expression and publication path. Session animation timing and native material/RGB565 differences have their own scope; the shadow tests do not establish complete Web PBR equivalence or board behavior.

Split presentation reuses this scratch sequentially for both cube matrices. Each emitted Instance is already immutable in the CB; changing the second cube cannot overwrite the first shadow. Both shadow groups precede both opaque cubes.

The separate `bloxorz_shadow_batch` target keeps every full-frame pixel difference, raw color/depth buffer and source snapshot. It isolates nearest-grid quantization with the old triangle path from the shared-Model path, checks two simultaneously live split slots, and samples a complete roll plus bridge, goal-hole, fragile-drop and negative-boundary receivers. Its native CPU comparison uses one total-shadow marker pair on both arms, excluding geometry dumps and per-triangle probes while including packing, stores and public draw preparation. This qualification permits explicitly reported tiny coverage differences; it does not claim exact Web raster equivalence, physical timing or board behavior. The host frame-schedule fixture additionally exercises the actual ordinary lifecycle without injecting hooks: two visible split cubes retain distinct slot keys and public storage facts across three frames, and finite exit coalesces the entire application heap. Historical exact-triangle controls deliberately omit batch ownership and retain their original exact-pixel contract.
